# Galka LIVE Hardened v3

Дата сборки: 2026-07-22

## Статус

Это усиленная fail-closed версия реального Hyperliquid-терминала. Критические действия больше не считаются успешными только потому, что локальная программа отправила запрос: результат проверяется по ответу операции и затем повторно сверяется с фактическими позициями и ордерами биржи.

Сборка прошла локальный набор тестов, однако это не означает нулевой риск. До проверки на конкретном Termux, конкретном API Wallet и реальном Hyperliquid-аккаунте LIVE должен оставаться выключенным.

## Что теперь защищено

- Реальная позиция Hyperliquid является источником истины.
- Отмена не получает статус `canceled`, пока биржа несколько раз не подтвердила отсутствие позиции и owned-ордеров.
- Аварийное закрытие не получает статус `emergency_closed`, пока биржа не подтвердила flat и удаление ордеров.
- Ответы order/cancel/leverage проверяются целиком, включая каждый элемент массива `statuses`.
- Неизвестный или ручной fill блокирует автоматический L1 rearm.
- При расхождении позиции, постороннем ордере, short-позиции, повреждении state или ошибке сверки включается `SAFE MODE`.
- Повреждённый state не заменяется тихо пустым состоянием.
- State сохраняется атомарно с `fsync` и правами `0600`.
- После перезапуска выполняется синхронная сверка с биржей до готовности интерфейса.
- Фоновый монитор контролируется; новая кампания не создаётся, если запущенный monitor thread умер.
- Сетевые запросы имеют таймаут; повторяются только read-запросы, но не торговые команды.
- Критические запросы обходят короткий UI-кэш.
- Разрешены три параллельные LIVE-кампании: по одной независимой кампании для BTC, ETH и SOL.
- Вторая одновременная кампания по той же монете запрещена, потому что Hyperliquid объединяет её в одну net-позицию.
- Перед новой кампанией BTC/ETH/SOL должны быть полностью чистыми от позиций и ордеров.
- Разрешён только isolated margin.
- Начальная маржа ограничивается долей свободных средств через `HL_MAX_MARGIN_FRACTION`.
- Внешний JavaScript/CDN из LIVE-страницы удалён.
- Локальный API защищён случайным session token, проверкой Host/Origin/Sec-Fetch-Site и CSP.
- Статический сервер не отдаёт Python-код, конфигурацию и остальные файлы репозитория.

## Важные границы

- Стратегия по-прежнему не имеет автоматического stop-loss. Глубокое продолжение падения может привести к крупному убытку или ликвидации isolated-позиции.
- Native TP — reduce-only trigger-limit на цене GALKA. При проблемах ликвидности или биржи мгновенное исполнение не гарантируется.
- Если Android остановит Termux, локальный rearm и сверка остановятся. Уже принятый биржей native TP остаётся на Hyperliquid, но локальная автоматизация возобновится только после запуска и сверки.
- Preview учитывает заданные maker/taker комиссии, но не будущий funding и не возможное проскальзывание аварийного IOC.
- Номинал `$1000` разрешён конфигурацией, но не должен использоваться до поэтапной реальной проверки меньших объёмов.

## Новые параметры конфигурации

```text
HL_ISOLATED=true
HL_MAX_MARGIN_FRACTION=0.60
HL_REQUEST_TIMEOUT=8
HL_MONITOR_INTERVAL=6
HL_GLOBAL_CHECK_INTERVAL=30
HL_MAKER_FEE_RATE=0.00015
HL_TAKER_FEE_RATE=0.00045
```

Допустимый `HL_TOTAL_NOTIONAL`: от `$80` до `$1000`. Фактический минимум может быть выше из-за восьми ордеров по минимум `$10` и округления размера.

## Локальная проверка без торговых команд

```bash
cd ~/GalkaLive
bash scripts/verify-galka-live.sh
```

Затем обязательно с LIVE OFF:

```bash
sed -i 's/^HL_LIVE_ENABLED=.*/HL_LIVE_ENABLED=NO/' ~/.config/galka-live.env
bash scripts/check-galka-live-account.sh
```

Read-only check выводит только замаскированные адреса, баланс, mids, позиции и количество открытых ордеров. Торговые команды не отправляются.

## Запуск

```bash
cd ~/GalkaLive
bash scripts/start-galka-live.sh
```

URL каждой сессии содержит случайный token во фрагменте. Launcher передаёт его браузеру, JavaScript удаляет token из адресной строки и затем отправляет через `X-Galka-Session`.

## Безопасный порядок допуска к LIVE

1. Установить обновление и принудительно оставить `HL_LIVE_ENABLED=NO`.
2. Выполнить `verify-galka-live.sh`.
3. Выполнить `check-galka-live-account.sh`; убедиться, что адрес и баланс правильные, а BTC/ETH/SOL чистые.
4. Запустить терминал в READ ONLY и проверить график, счёт, сеть и события.
5. Сделать контролируемый smoke test на минимальном приемлемом номинале после preview.
6. Проверить в официальном интерфейсе Hyperliquid: восемь ALO-входов, native TP, fill, закрытие и отсутствие хвостовых ордеров.
7. Проверить L1 rearm и завершение после L2+.
8. Только после нескольких чистых полных циклов без SAFE MODE/recovery увеличивать объём ступенями. `$1000` — последний этап, а не первый.

При любом `SAFE MODE` новые кампании заблокированы. Сначала проверяется официальный интерфейс Hyperliquid, затем используется кнопка `Сверить`. SAFE MODE снимается только при чистом фактическом состоянии.
